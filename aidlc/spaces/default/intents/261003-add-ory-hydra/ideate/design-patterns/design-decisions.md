# Design Decisions — M2M

| # | Decision | Pattern | Why |
| --- | --- | --- | --- |
| MD-1 | `MachineTokenVerifier` port, `hydra` adapter (go-jose JWKS + JWT) | Port/adapter | Swap issuer (Ory Network, another AS) without touching handlers |
| MD-2 | Offline JWT + cached client-status | Cache-aside revocation | No per-request network call, revocation ≤ 30 s |
| MD-3 | JWKS cache with refresh-on-unknown-kid, rate-limited | Key rollover | Survives Hydra key rotation without restarts; resists kid-flooding |
| MD-4 | `Policy{Plane: PlaneMachine, Scope}` in `RoutePolicies` | Declarative fail-closed authz | Same startup check as other planes |
| MD-5 | Hydra is the client store; metadata marks ownership | Single source of truth | No duplicate table to drift |
| MD-6 | Secret generated by Hydra (create) / service (rotate), returned once, never stored | Show-once secret | Industry norm (GitHub/Stripe style) |
| MD-7 | Create = reserve key → Hydra → tx (audit + idempotency) → compensate on failure | Saga/compensation (as admin invite) | No orphaned clients |
| MD-8 | Machine responses are PII-free DTOs | Data minimisation | Machines don't get personal data without a separate design |
